# AI usage

I built Mentari with AI coding agents. This file says how: the workflow, what the agents generated, and what I did
myself. The session numbers are from the project's own records up to 24 November 2026. The test counts are from the
public CI run [45331029642](https://github.com/aimanmalib/mentari/actions/runs/45331029642) on 24 November 2026.

## Workflow

I worked with Claude models through Claude Code, in three separate roles. Each role runs as its own session and does not
share memory with the others; they talk through files in the repository and a plan.

1. **Planner.** An agent read the fest rules, the prize page, the FAQ, the official QoreChain docs and the workshop
   examples, and wrote a product requirements document: the problem, the design decisions with reasons, the testnet
   evidence to collect, the risks, and a plan cut into small slices. I read it and approved it before any code was
   written.
2. **Builder.** An agent takes the next slice in the plan, builds it, runs the related tests, and commits in small
   steps. One slice per session. It may only change the files the slice needs.
3. **Reviewer.** A separate agent, started fresh, reads the diff and the running result. It breaks the code on purpose
   (for example, removes a check) to see whether a test turns red, and looks at screenshots of the site on desktop, on a
   320 px screen and in WebKit on an iPhone 13 profile. It can reject the slice.

Between the builder and the reviewer there is a mechanical gate that no agent can talk its way past: the whole test
suite on a remote CI runner, contract coverage of at least 90 %, `forge fmt --check`, a secret scan of the history,
a limit on file length, and a check that the slice only touched files in its scope. A slice that fails the gate or the
review is not accepted, and the next session fixes it.

Rules the agents work under: testnet only; no keys or seed phrases in the repository, logs or screenshots; every number
in public text must come from a test run or from `evidence/`; no public post, form, payment or message to the organisers
in my name.

## Generated work

Almost everything in this repository was generated by AI agents and accepted through the workflow above:

- the Solidity contracts and libraries, and all 115 Foundry tests (unit, fuzz and invariant);
- the Node server, the site, the testnet scripts, and their 541 vitest tests;
- the 10 browser tests that run in Chromium and WebKit;
- the deploy script, container image, health watch and CI workflow;
- the English and Bahasa Melayu text of the site, this README, the decision records and the other documents;
- the logo, which reuses the sun mark the builder drew for the site, and the screenshots, which a script captured from
  the running site.

Up to 24 November 2026 the builder ran 45 sessions. 35 were accepted. 2 stopped on purpose to wait: once for the test
funds, and once for a new UTC day, which the meter cases E and F needed. 8 were not accepted:

| Slice | Caught by | What was wrong | Fix |
| --- | --- | --- | --- |
| Contract library and test gate | the mechanical gate | the builder gave the secret scanner an allowlist of folders to skip; scanner settings are my call, not an agent's | allowlist removed; the scan now copies only the files git would publish and uses the default rules |
| The same slice, second try | the reviewer | allowing `"` in the memo alphabet did not turn any test red | a test over all 256 byte values against the alphabet; the same sabotage now fails |
| Retirements, Verify and Try it pages | the reviewer | a button label broke in the middle of a word on narrow phones | CSS fixed, and a screenshot check for broken words in buttons and navigation |
| README, AI usage and community files | the reviewer | `SECURITY.md` sent reporters to GitHub private vulnerability reporting, which is off on this repository; the contract test breakdown in the README did not add up; the Malay README had no threat summary | reports go to an e-mail address; the README explains how forge counts the invariant suite; the Malay README has the requirements table and the threat summary |
| Slides | the reviewer | slide 6 gave an old site test count, copied from a README that was out of date too | count fixed, and a test now checks every slide number against the README |
| Cover image and project card | the reviewer | the last slide still said no retirement was recorded, after retirements were on the testnet | slide text taken from `evidence/` |
| Judge package check and explorer links | the reviewer | Retirements and Verify showed no transaction links: the public node refuses log searches over 10,000 blocks, and the site hid the error | logs are searched in 10,000-block windows, and a receipt from the Native lane links the Native transaction that wrote it (decisions 0033 and 0034) |
| Test count refresh | the reviewer | the README still dated the new server and site counts 22 November | date line fixed in both READMEs |

Other AI mistakes caught before they reached a judge:

- After the repository went public, GitHub Actions failed on the first run: the script that counts vitest tests did not
  strip terminal colour codes, which Actions turns on. A regression test now fails on the old code
  ([`9b5c17d`](https://github.com/aimanmalib/mentari/commit/9b5c17d)).
- In the screenshot review, a time like "9:00 PG" wrapped so the "PG" sat alone on a line, and a double rule appeared at
  the end of the registry list. Both were fixed with a regression test.
- The test gate miscounted tests when pnpm prefixed each line with the package name; it was fixed with a test that is
  red on the old pattern.

## Human contribution

I am a solo builder. These parts are mine and are not delegated to an agent:

- **Deciding.** Entering the fest, the Cross-VM track, and approving the requirements document, which fixes the use case
  (solar certificates), the Native target (`qday-receipts`), the post-quantum rules and what is out of scope.
- **Design direction.** I approved the visual direction of the site before the pages were built.
- **Accounts and money.** Registering on the fest site, holding the test wallet, and funding the test accounts from the
  faucet. The agents never hold my login.
- **Publishing.** Creating the project page, reviewing and uploading the video, and anything posted in my name.
- **Judgement calls the agents escalate to me.** Anything about money, public wording about me, or access I have not
  given.

The narration in the demo video is a clone of my own voice, made with ElevenLabs, and the end card says so. Agents
wrote the narration lines, captured the live site with Playwright and built the film; I listen to it before I publish
it. The music is by Sascha Ende, ende.app (CC BY 4.0). How the video is built: [decision 0032](docs/decisions/0032-demo-video.md).
